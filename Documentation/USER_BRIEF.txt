8. ИСТОРИЯ
============================================================

Не перегружай игру текстом.

Главное повествование идёт через:

- окружение;
- маленькие анимационные сцены;
- найденные осколки воспоминаний;
- расположение вещей;

- изменение дома.

Главный герой — сказочный домашний дух.

Не утверждать, что он является умершим человеком.

Не использовать:

- реальную оккультную символику;

- реальные магические ритуалы;

Атмосфера:

немного одинокая;
уютная;
меланхоличная;
сказочная;
не страшная.

Сюжетная линия:

Привидение просыпается на чердаке.

Дом почти полностью погружён в тишину.

Где-то далеко слышен очень слабый звук музыкальной шкатулки.

По мере продвижения герой понимает, что многие механизмы дома остановились.

Центральные огромные часы в холле замерли.

Игрок постепенно восстанавливает «жизнь» дома:

зажигает свет;
запускает механизмы;
возвращает движение;
находит воспоминания;
возвращает музыку.

Финальная цель:

добраться до больших часов в центральном холле и запустить их.

После запуска:

по дому проходит мягкая волна;
оживают механизмы;
окна начинают светлеть от рассвета;
музыкальная тема раскрывается полностью.

При сборе 100% воспоминаний показать небольшую дополнительную сцену.

============================================================
12. ОБРАБОТКА ИСХОДНОЙ КАРТИНКИ
============================================================

Важный момент:

исходная картинка может иметь нарисованный шахматный фон.

Это может быть НЕ настоящая transparency.

НЕ применяй:

«удалить все белые пиксели».

Само привидение белое.

Если фон является baked checkerboard:

создай Editor-processing tool.

Алгоритм:

1. Проанализировать пиксели по краям.
2. Определить основные цвета фоновой шахматной сетки.
3. Flood-fill выполнять ТОЛЬКО от границ изображения.
4. Фоновые connected pixels сделать alpha = 0.
5. Внутренние белые части персонажа сохранить.
6. Сохранить cleaned copy.
7. Никогда не перезаписывать исходник.

Добавь tolerance, но не слишком большой.

После обработки визуально и программно убедись:

- фон прозрачный;
- тело не имеет дыр;
- глаза сохранены;
- края не испорчены.

13. PIXEL ART IMPORT
============================================================

Для игровых sprites:

Texture Type = Sprite

Filter Mode = Point

Mip Maps = Off

Wrap Mode = Clamp там, где подходит.

Compression:

подобрать для Web так, чтобы pixel-art не покрывался заметными артефактами.

Использовать единый Pixels Per Unit.

Рекомендуемая отправная точка:

32 PPU.

Но если размер существующего персонажа требует другого логичного PPU — выбери единый стандарт.

14. ГРАФИЧЕСКИЙ СТИЛЬ
============================================================

Окружение должно выглядеть так, будто его рисовал тот же автор, который сделал привидение.

Стиль:

минималистичный monochrome pixel-art.

Не использовать:

реалистичные текстуры;
3D;
гладкий flat vector;
современный неоновый интерфейс;
фотореализм;
сложные gradients;
стоковые фотографии.

Палитру лучше получить на основе cleaned ghost sprite.

Создай:

GhostPalette / GamePalette.

Возьми основные светлые/серые/тёмные оттенки персонажа.

Расширь палитру только настолько, насколько нужно для окружения.

Ориентир:

5–8 оттенков серого.

Например уровни:

near-white
light gray
mid-light gray
mid gray
dark gray
near-black

Глаза и самые тёмные опасности могут использовать near-black.

============================================================
16. PIXEL PERFECT
============================================================

Игра должна сохранять pixel-art визуал.

Используй Pixel Perfect Camera или эквивалентную систему.

Ориентировочное внутреннее разрешение:

480×270

или другое близкое 16:9 разрешение, которое лучше соответствует реальному размеру sprite персонажа.

Pixel Perfect правила:

- Point filtering;
- integer-friendly scaling;
- без размытия;
- camera render positions корректно снапятся;
- gameplay sprites не должны дрожать между пикселями.

Плавное движение допускается в world coordinates.

Но окончательное отображение должно быть визуально стабильным.

18. УПРАВЛЕНИЕ ПРИВИДЕНИЕМ
============================================================

Движение — один из главных показателей качества.

НЕ делай примитивно:

velocity.x = input * speed

без нормальной настройки.

Реализуй:

acceleration;
deceleration;
ground acceleration;
air acceleration;
ground friction;
maximum horizontal speed;
variable jump height;
coyote time;
jump buffering;
fall gravity multiplier;
low-jump gravity;
maximum fall speed;
soft landing;
ground snapping только если действительно нужно;
one-way platform support.

Начальные ориентиры:

coyote time:
0.10–0.14 s

jump buffer:
0.10–0.15 s

Не воспринимай цифры как жёсткие.

Создай:

GhostMovementConfig ScriptableObject.

Все основные tuning values вынести туда.

============================================================
19. ПРЫЖОК
============================================================

Прыжок должен быть приятным и читаемым.

Нажал:
сильный прыжок.

Отпустил кнопку раньше:
прыжок становится ниже.

При падении:
gravity немного сильнее.

В верхней точке:
очень короткое мягкое hang-time ощущение.

НЕ делай героя тяжёлым как камень.

Он привидение.

Но не превращай движение в полностью свободный flight.

============================================================
20. ЛЁГКОЕ ПАРЕНИЕ
============================================================

Привидение не летает бесконечно.

Добавь очень небольшое характерное поведение:

например после отпускания jump в воздухе возможно небольшое смягчение падения.

Но не ломай платформер.

Допустимый вариант:

при удержании Jump во время падения первые ~0.3–0.5 секунды fall gravity немного уменьшается.

Это должно ощущаться как:

«привидение чуть легче воздуха»

а не как:

«у персонажа есть jetpack».

============================================================
24. IDLE ANIMATION
============================================================

Idle:

- плавное парение вверх-вниз;
- амплитуда примерно 1–3 pixel-art пикселя;
- очень лёгкое покачивание;
- лёгкий squash/stretch;
- редкое моргание;
- маленькое движение хвоста через rotation/scale deformation, если возможно.

Не делай motion слишком заметным.

============================================================
25. MOVEMENT ANIMATION
============================================================

При движении:

- персонаж слегка наклоняется;
- визуальная часть немного отстаёт от physical root;
- хвост/нижняя часть имеет небольшой lag;
- scale слегка реагирует на скорость;
- направление хорошо читается без зеркалирования глаз в странную сторону.

Если flip X визуально подходит — используй.

Если sprite симметричный — можно оставить.

============================================================
26. JUMP / FALL / LAND
============================================================

Jump:

короткий anticipation squash.

После отрыва:

stretch по вертикали.

Fall:

чуть более широкий силуэт.

Land:

быстрый squash
→
overshoot
→
neutral.

Добавить 2–5 маленьких pixel particles при сильном приземлении.

============================================================
27. МОРГАНИЕ
============================================================

Добавь моргание.

Предпочтительные варианты:

1. На edit-time создать отдельный blink sprite из cleaned sprite.
или
2. маленький BlinkLayer поверх глаз.

Не делай моргание через уродливое закрытие половины лица.

Моргание редкое и случайное:

примерно один раз каждые несколько секунд с variation.

============================================================
28. POSSESSION ANIMATION
============================================================

При вселении:

1. Управление на короткое время блокируется.
2. Привидение сжимается.
3. Быстро летит/втягивается в предмет.
4. Появляется небольшое pixel-ring / spark.
5. Ghost visual исчезает.
6. Предмет получает possessed-state feedback.

Вся анимация:

примерно 0.2–0.4 секунды.

Быстрая.

============================================================
29. EXIT POSSESSION
============================================================

При выходе:

1. Найти безопасную точку около объекта.
2. Появляется небольшая частица.
3. Ghost scale:
0
→
1.1
→
1.
4. Возвращается управление.

Нельзя позволять появиться:

- внутри стены;
- внутри пола;
- внутри опасности.

Реализуй SafeExitSolver.

============================================================
30. АРХИТЕКТУРА POSSESSION
============================================================

Создай расширяемую architecture.

Пример:

IPossessable

PossessableBehaviour

PossessionController

PossessionContext

PossessionInput

Каждый объект должен предоставлять:

CanPossess()
EnterPossession()
ExitPossession()
HandleInput()
GetCameraTarget()
GetExitCandidates()

Не обязательно использовать ровно такие имена.

Главное:

новый тип possessable можно добавить без переписывания GhostController.

============================================================
31. ROUTING INPUT
============================================================

Input должен маршрутизироваться через единый abstraction.

Когда игрок — Ghost:

input получает GhostController.

Когда игрок внутри предмета:

input получает текущий Possessable.

UI не должен напрямую дергать LampPossessable.

Используй:

PlayerInputRouter

или аналог.

============================================================
32. INTERACTION
============================================================

Когда Ghost подходит к предмету:

предмет получает аккуратный визуальный highlight.

Не использовать гигантские сияющие outline.

Например:

- 1 pixel outline;
- лёгкое пульсирование;
- маленькая иконка;
- небольшой контраст.

На desktop появляется:

E

На мобильном:

контекстная кнопка/иконка.

============================================================
33. POSSESSABLE №1 — ЛАМПА
============================================================

LampPossessable.

Игрок вселяется в настольную/подвесную лампу.

Может:

включить/выключить свет.

Свет:

- проявляет hidden platforms;
- проявляет secret symbols;
- заставляет shadow hazard отступить;
- активирует light-sensitive switches;
- показывает скрытые collectibles.

Не делай лампу оружием.

Игрок не убивает существ.

34. HIDDEN PLATFORM
============================================================

Hidden

FadingOut

platform materializes.

Collider включается только когда платформа достаточно проявилась.

Добавь визуальный hint, чтобы загадка была честной.

============================================================
35. POSSESSABLE №2 — ВЕНТИЛЯТОР
============================================================

FanPossessable.

Управление:

включить/выключить.

В некоторых вариантах:

изменить направление.

AirFlowZone:

- воздействует на Ghost;
- двигает лёгкие предметы;
- колышет декорации;
- позволяет Ghost подняться;
- толкает небольшие ящики/бумагу.

Физика должна быть предсказуемой.

Не использовать огромную AddForce каждый кадр.

============================================================
36. POSSESSABLE №3 — ИГРУШЕЧНАЯ МАШИНКА
============================================================

ToyCarPossessable.

У машины собственный Rigidbody2D.

Она:

- быстро ездит;
- проходит под низкими препятствиями;
- может съезжать с небольших рамп;
- нажимать floor switches;
- перевозить маленький объект;
- проникать в участки, куда Ghost не может пройти из-за специальных потоков/барьеров.

Управление должно быть простым.

Не превращать игру в racing game.

============================================================
37. POSSESSABLE №4 — ЧАСЫ
============================================================

ClockPossessable.

Time.timeScale

для этой способности.

ITimeAffected.

Например:

MovingPlatform;
Pendulum;
ClosingDoor;
Gear;
Crusher;
SteamValve.

ClockPossessable позволяет:

Например:

1.0
→
0.25

Ghost продолжает двигаться нормально.

============================================================
38. POSSESSABLE №5 — ТЯЖЁЛЫЙ ПРЕДМЕТ
============================================================

HeavyPossessable.

Это может быть:

- статуэтка;
- тяжёлая игрушка;
- деревянная фигура.

Особенности:

- медленное движение;
- почти не сдувается ветром;
- активирует pressure plates;
- ломает brittle floor в специальных местах;
- может служить ступенькой после выхода Ghost.

Нельзя использовать для убийства существ.

============================================================
39. POSSESSABLE №6 — МУЗЫКАЛЬНАЯ ШКАТУЛКА
============================================================

MusicBoxPossessable.

При активации создаёт музыкальный pulse.

Pulse:

- проявляет spectral platforms;
- активирует resonance mechanisms;
- показывает collectibles;
- временно успокаивает некоторые hazards.

Music platforms существуют ограниченное время.

Игрок должен использовать их для platforming puzzle.

→

43. FAIL STATE
============================================================

Не показывать:

GAME OVER

после каждого падения.

Вместо этого:

- freeze ~0.1 sec;
- pixel dissolve;
- короткий fade;
- respawn на checkpoint.

Весь цикл:

примерно 1–2 секунды.

Игрок быстро возвращается в gameplay.

44. CHECKPOINT
============================================================

- collectibles;
- прогресс.

Checkpoint визуально обозначать очень аккуратно.

Например:

============================================================
45. RESET PUZZLE
============================================================

Игрок не должен soft-lock игру.

Каждая головоломка, где объект можно физически потерять, имеет:

Пример:

удержание R на desktop

или кнопка pause → Restart puzzle.

Reset восстанавливает только текущую puzzle room.

Не весь уровень.

============================================================
46. LEVEL DESIGN PHILOSOPHY
============================================================

Каждая загадка должна содержать:

1. Наблюдение.
2. Понятную проблему.
3. Доступный инструмент.
4. Момент понимания.
5. Короткое выполнение.
6. Feedback успеха.

Не использовать:

- обязательные невидимые переключатели;
- pixel hunting;
- случайность;
- длинные ожидания;
- наказание за экспериментирование.

47. ОБУЧЕНИЕ
============================================================

Первые минуты:

Ghost просыпается.

Игрок сам учится:

двигаться;
прыгать;
взаимодействовать;
вселяться.

Подсказки contextual.

Не показывай окно:

«Добро пожаловать! Вот 15 страниц управления».

Пример:

после появления:

A / D

после движения исчезает.

У первой пропасти:

Space

У первой Lamp:

После изучения tutorial flag сохранить.

Больше не показывать его при продолжении игры.

3–5.

Общее количество:

примерно 20.

Часть должна требовать:

- наблюдения;
- света;
- ветра;
- car route;
- music pulse;
- timing puzzle.

Не отправлять network save каждый кадр.

Использовать debounce.

Ориентир:

несколько KB.

Не затирай явно более новый прогресс более старым cloud save.

Логику вынести в:

============================================================
86. YANDEX PLUGIN
============================================================

Основной интеграционный способ:

официально рекомендованный для Unity:

Plugin Your Games 2.0.

Сначала проверь:

установлен ли plugin в проекте.

Если установлен:

изучи его реальный namespace, modules и API.

Если plugin скачан в виде package/unitypackage, но не импортирован и доступен локально:

аккуратно импортируй/подключи его подходящим способом, если это возможно без повреждения проекта.

Если plugin отсутствует:

НЕ ИЗОБРЕТАЙ API.

Создай platform abstraction и LocalPlatformService.

В отчёте явно укажи, что импорт plugin является единственным ручным блокером Yandex-интеграции.

НО остальную игру продолжай разрабатывать.

90. GAMEPLAY API
============================================================

- уровень загружен;
- игрок получил управление;
- resume.

GameplayAPI.stop()

когда:

- открыта Pause Menu;
- level completed;
- gameplay остановлен;
- идёт реклама;
- смена browser tab/platform pause;
- portrait block;
- ending/cutscene, если игрок реально не управляет gameplay.

Не спамить start/stop каждый кадр.

============================================================

game_api_pause
game_api_resume

На pause:

- игровой control блокируется;
- physics/game time останавливаются;
- audio останавливается;
- соответствующее gameplay состояние сохраняется.

На resume:

не делать безусловно:

Time.timeScale = 1

Сначала проверить:

ManualPause?
OrientationPause?
Ad?
Menu?
Cutscene?
